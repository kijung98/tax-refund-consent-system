# 국세환급금 동의서 업무보조 웹 시스템

납세자가 스마트폰(QR/URL 접속)으로 동의서를 작성하고, 세무서 담당자가 관리자 페이지에서
확인·검색·엑셀 다운로드·출력하는 업무보조 시스템입니다.

**현재 개발 범위(1단계 MVP)**: 종합부동산세 공동명의 1주택자 특례(변경)신청서(FORM B) 한 종만
전체 흐름이 동작합니다. 국세환급금양도요구서(FORM A), 국세환급금 충당청구(동의)서(FORM C)는
DB 테이블 구조만 준비되어 있고, 입력 화면은 2단계에서 추가합니다.

## 2. 설치 및 로컬 실행 방법 (비개발자용)

1. 이 폴더 전체를 컴퓨터에 저장합니다.
2. 아래 "3. Backend(Supabase) 연결 방법"을 먼저 완료해서 `js/config.js`를 채웁니다.
3. `taxpayer/index.html` 을 크롬 브라우저로 더블클릭해서 열면 납세자 화면이 바로 보입니다.
   (단, 일부 브라우저는 `file://` 로 열면 보안 정책상 제대로 동작하지 않을 수 있어
   아래 "간단한 로컬 서버 실행"을 권장합니다.)

**간단한 로컬 서버 실행 (선택, 더 안정적)**
- VS Code 사용시: "Live Server" 확장 설치 후 `index.html`에서 우클릭 → Open with Live Server
- 또는 터미널에서: `npx serve .` 실행 후 안내되는 주소로 접속

## 3. Backend(Supabase) 연결 방법 — ⭐ 가장 먼저 해야 할 작업

1. https://supabase.com 접속 → 무료 계정 생성 → 새 프로젝트(Project) 생성
   (리전은 Northeast Asia(Seoul) 권장)
2. 프로젝트 생성 완료 후, 왼쪽 메뉴에서 **SQL Editor** 클릭
3. 이 저장소의 `sql/schema.sql` 파일 내용 전체를 복사 → SQL Editor에 붙여넣기 → **Run** 실행
   - 실행 후 왼쪽 **Table Editor** 메뉴에서 `submissions`, `form_b_joint_home` 등
     테이블이 생성되었는지 확인합니다.
4. 왼쪽 메뉴 **Project Settings → API** 이동
   - **Project URL** 값을 복사 → `js/config.js` 의 `url` 에 붙여넣기
   - **anon public** 키 값을 복사 → `js/config.js` 의 `anonKey` 에 붙여넣기
5. 저장 후 `admin/index.html` 을 열어서 목록이 정상적으로 불러와지는지(빈 목록이라도 오류가
   없는지) 확인합니다.

### 환경변수/키 관리 주의사항
- `anonKey`는 Supabase 설계상 "브라우저에 노출되어도 되는" 공개키입니다. 다만 GitHub에
  공개 저장소로 올릴 경우 불특정 다수가 이 키로 데이터를 넣거나 읽을 수 있으므로,
  **RLS(행 단위 보안) 정책을 반드시 운영 수준으로 강화**해야 합니다 (아래 5번 참고).
- 더 안전하게 하려면 GitHub 저장소를 **Private**로 만들고 GitHub Pages 대신
  사설 호스팅(또는 조직 내부망)을 사용하는 것도 고려하세요.

## 4. GitHub 업로드 및 GitHub Pages 배포 방법

1. GitHub에서 새 저장소(Repository) 생성 (예: `tax-refund-consent`)
2. 이 폴더 전체를 저장소에 업로드 (GitHub 웹사이트의 "Add file → Upload files" 기능 이용 가능,
   또는 `git` 명령어에 익숙하면 `git init` → `git add .` → `git commit` → `git push`)
3. 저장소 메뉴에서 **Settings → Pages** 이동
4. **Branch**: `main`(또는 `master`), 폴더는 `/ (root)` 선택 → **Save**
5. 몇 분 후 `https://본인아이디.github.io/저장소이름/` 형태의 주소가 생성됩니다.
   이 기본주소로 접속하면 루트의 `index.html`이 열려 **납세자 화면 / 관리자 화면**을
   선택하는 페이지가 바로 나타납니다.
6. 납세자용 직접 주소: `https://본인아이디.github.io/저장소이름/taxpayer/index.html`
   관리자용 직접 주소: `https://본인아이디.github.io/저장소이름/admin/index.html`
   (QR코드에는 보통 납세자용 직접 주소를 사용합니다 — 7번 QR 생성 방법 참고)

## 5. 보안 체크리스트 (⚠️ 실제 운영 전 반드시 확인)

현재 버전은 **프로토타입**입니다. 아래 항목은 실제 납세자 개인정보를 다루기 전
반드시 처리해야 합니다.

| 항목 | 현재 상태 | 필요 조치 |
|---|---|---|
| 관리자 페이지 접근 제한 | 없음 (URL만 알면 누구나 접속) | Supabase Auth 로그인 또는 별도 인증 추가 |
| RLS 정책 | 익명 전체 허용(프로토타입용) | 관리자만 조회 가능하도록 정책 강화 (`sql/schema.sql` 주석 참고) |
| 주민등록번호 저장 | 평문 저장 | 암호화 저장 또는 마스킹 표시, 보관기간 정책 수립 |
| 전송 구간 암호화 | GitHub Pages는 기본 HTTPS 적용 | Supabase도 기본 HTTPS이므로 별도 조치 불요 (확인만 권장) |
| 접근 로그/감사 로그 | 없음 | 운영 전환시 조회/수정 이력 로그 테이블 추가 검토 |
| 전자서명의 법적 효력 | 확인되지 않음 | 소속 기관(세무서)의 전자서명 인정 여부 사전 확인 필요 |
| 실제 개인정보 테스트 | 절대 사용 금지 | 테스트는 가상 데이터(홍길동/김영희 등)만 사용 |

## 6. 테스트 방법 / 테스트 시나리오

| 번호 | 시나리오 | 기대 결과 |
|---|---|---|
| TEST 01 | 신청유형 "최초" + 점검항목 3개 모두 체크 + 서명 + 제출 | 제출 가능, 접수번호 발급 |
| TEST 02 | 신청유형 "최초" + 점검항목 일부만 체크 | 다음 단계로 진행 불가(오류 표시) |
| TEST 03 | 신청유형 "특례취소" + 점검항목 미체크 | 제출 가능 (취소는 점검항목 필수 아님) |
| TEST 04 | 배우자 동의 확인 체크 안함 | 제출 불가 |
| TEST 05 | 서명 없이 제출 시도 | 제출 불가 |
| TEST 06 | 주민등록번호를 잘못된 형식으로 입력 | 오류 메시지 표시, 다음 단계 진행 불가 |
| TEST 07 | 정상 제출 후 관리자 목록에서 확인 | 목록에 즉시 표시됨 (새로고침 필요할 수 있음) |
| TEST 08 | 관리자 상세보기에서 서명 이미지 확인 | 서명 이미지 정상 표시 |
| TEST 09 | 관리자 상태 변경(신규→확인중) 후 저장 | 목록/상세 모두 반영 |
| TEST 10 | 관리자 엑셀 다운로드 | 입력한 데이터가 엑셀 행으로 정상 출력 |
| TEST 11 | A4 인쇄 미리보기 (detail.html → 인쇄 버튼) | 원본 서식과 유사한 레이아웃으로 표시 |
| TEST 12 | 스마트폰 실기기에서 폼 작성 | 글자 잘림/버튼 눌림 문제 없이 작성 가능 |

가상 테스트 데이터 예시: 신청인 홍길동(900101-1234567), 배우자 김영희(900101-2345678),
전화번호 010-0000-0000, 주소 "테스트 주소"

## 7. QR 코드 생성 방법

1. `admin/qr.html` 접속
2. "납세자 접속 페이지 기본 주소"에 GitHub Pages 배포 후 주소를 입력
   (예: `https://본인아이디.github.io/tax-refund-consent/taxpayer/index.html`)
3. 필요시 참조번호(세무서 내부 관리용, 선택) 입력 후 "QR 생성"
4. 생성된 QR 이미지를 저장하여 납세자에게 인쇄물 또는 카카오톡 등으로 전달

## 8. 관리자 페이지 접속 방법

- 목록/검색: `admin/index.html`
- 상세보기: 목록에서 "상세" 버튼 클릭
- QR 생성: `admin/qr.html`
- ⚠️ 현재 별도 로그인 절차가 없습니다. 내부망 또는 URL 비공개 공유 등으로 임시 보호하고,
  운영 전환시 반드시 인증을 추가하세요 (5번 보안 체크리스트 참고).

모바일·우편으로 개별 안내하는 서비스를 시작했습니다. 이는 국세청이 자체적으로 제공하는
안내 서비스이며, 납세자가 별도로 작성·제출하는 공식 "동의서" 서식은 아닙니다.
(2026.9.13. 국세청장 발표 기준, 출처: 언론보도 — 국세청 공식 공지사항으로 재확인 권장)

반영해 두었으며, 실제 신청/취소는 공식 서식인 FORM B(공동명의 1주택자 특례신청서)로
