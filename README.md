# 국세환급금 동의서 업무보조 웹 시스템

납세자가 스마트폰(QR/URL 접속)으로 동의서를 작성하고, 세무서 담당자가 관리자 페이지에서
확인·검색·엑셀 다운로드·출력하는 업무보조 시스템입니다.

**현재 개발 범위(5단계 완료)**: 국세환급금양도요구서(FORM A), 종합부동산세 공동명의
1주택자 특례(변경)신청서(FORM B), 국세환급금 충당청구(동의)서(FORM C) **3종 서식**의
전체 흐름(모바일 입력 → 제출 → 관리자 확인 → 엑셀/A4출력)에 더해, **관리자 로그인
인증**, **RLS 보안 강화**, **주민등록번호 암호화 저장**까지 적용되었습니다.
남은 작업은 실제 사용성 테스트 등 운영 전환 마무리입니다 (아래 15번 참고).

## 2. 설치 및 로컬 실행 방법 (비개발자용)

1. 이 폴더 전체를 컴퓨터에 저장합니다.
2. 아래 "3. Backend(Supabase) 연결 방법"을 먼저 완료해서 `js/config.js`를 채웁니다.

   아래 "간단한 로컬 서버 실행"을 권장합니다.)

**간단한 로컬 서버 실행 (선택, 더 안정적)**
- VS Code 사용시: "Live Server" 확장 설치 후 `index.html`에서 우클릭 → Open with Live Server
- 또는 터미널에서: `npx serve .` 실행 후 안내되는 주소로 접속

## 3. Backend(Supabase) 연결 방법 — ⭐ 가장 먼저 해야 할 작업

1. https://supabase.com 접속 → 무료 계정 생성 → 새 프로젝트(Project) 생성
   (리전은 Northeast Asia(Seoul) 권장)
2. 프로젝트 생성 완료 후, 왼쪽 메뉴에서 **SQL Editor** 클릭
3. 이 저장소의 `sql/schema.sql` 파일 내용 전체를 복사 → SQL Editor에 붙여넣기 → **Run** 실행
   - 실행 후 왼쪽 **Table Editor** 메뉴에서 `submissions`, `form_b_joint_home` 등
     테이블이 생성되었는지 확인합니다.
4. 주민등록번호 암호화 키를 설정합니다 (10번 "주민등록번호 암호화 설정 방법" 참고):
   ```sql
   insert into app_secrets (key_name, key_value)
   values ('encryption_key', '본인이_정한_비밀키')
   on conflict (key_name) do update set key_value = excluded.key_value;
   ```
5. 왼쪽 메뉴 **Project Settings → API Keys** 이동
   - **Project URL** 값을 복사 → `js/config.js` 의 `url` 에 붙여넣기
   - **Publishable key** (`sb_publishable_...`로 시작, 예전 이름 "anon public") 값을
     복사 → `js/config.js` 의 `anonKey` 에 붙여넣기
   - 화면에 "Publishable and secret API keys" 탭과 "Legacy anon, service_role
     API keys" 탭 두 개가 보일 수 있습니다. 어느 탭이든 **"Publishable"** 또는
     **"anon"**이라고 적힌 키를 쓰면 됩니다.
   - 🚫 **"Secret key"(`sb_secret_...`) 또는 "service_role" 키는 절대 넣지
     마세요.** 이 키는 보안 규칙을 모두 무시하는 관리자 권한 키라서, 공개
     저장소에 올라가는 이 파일에 넣으면 전체 데이터가 노출됩니다.
6. 관리자 계정을 만듭니다 (9번 "관리자 로그인 설정 방법" 참고) — 로그인 없이는
   관리자 화면에서 데이터가 보이지 않습니다.
7. `admin/login.html`을 열어 방금 만든 계정으로 로그인 → `admin/index.html`에서
   목록이 정상적으로 불러와지는지(빈 목록이라도 오류가 없는지) 확인합니다.

### 환경변수/키 관리 주의사항
- `anonKey`(Publishable key)는 Supabase 설계상 "브라우저에 노출되어도 되는" 공개키입니다.
  실제 데이터 조회·수정은 관리자 로그인 여부로 RLS가 걸려있어 이 키만으로는 조회할 수 없습니다.
- 더 안전하게 하려면 GitHub 저장소를 **Private**로 만들고 GitHub Pages 대신
  사설 호스팅(또는 조직 내부망)을 사용하는 것도 고려하세요.

## 4. GitHub 업로드 및 GitHub Pages 배포 방법

1. GitHub에서 새 저장소(Repository) 생성 (예: `tax-refund-consent`)
2. 이 폴더 전체를 저장소에 업로드 (GitHub 웹사이트의 "Add file → Upload files" 기능 이용 가능,
   또는 `git` 명령어에 익숙하면 `git init` → `git add .` → `git commit` → `git push`)
3. 저장소 메뉴에서 **Settings → Pages** 이동
4. **Branch**: `main`(또는 `master`), 폴더는 `/ (root)` 선택 → **Save**
5. 몇 분 후 `https://본인아이디.github.io/저장소이름/` 형태의 주소가 생성됩니다.
   이 기본주소로 접속하면 루트의 `index.html`이 열려 **납세자 화면 / 관리자 화면**을
   선택하는 페이지가 바로 나타납니다.
6. 납세자용 직접 주소: `https://본인아이디.github.io/저장소이름/taxpayer/index.html`
   관리자용 직접 주소: `https://본인아이디.github.io/저장소이름/admin/index.html`
   (QR코드에는 보통 납세자용 직접 주소를 사용합니다 — 7번 QR 생성 방법 참고)

## 5. 보안 체크리스트 (⚠️ 실제 운영 전 반드시 확인)

현재 버전은 **프로토타입**입니다. 아래 항목은 실제 납세자 개인정보를 다루기 전
반드시 처리해야 합니다.

| 항목 | 현재 상태 | 필요 조치 |
|---|---|---|
| 관리자 페이지 접근 제한 | ✅ 적용됨 | Supabase Auth 로그인 필요 (`admin/login.html`, 9번 참고) |
| RLS 정책 | ✅ 적용됨 | 로그인한 관리자만 조회/수정 가능, 제출(insert)만 누구나 가능 |
| 주민등록번호 저장 | ✅ 암호화 적용됨 | DB 안에서 pgcrypto로 암호화/복호화 (10번 참고), 보관기간 정책은 별도 수립 필요 |
| 전송 구간 암호화 | GitHub Pages는 기본 HTTPS 적용 | Supabase도 기본 HTTPS이므로 별도 조치 불요 (확인만 권장) |
| 접근 로그/감사 로그 | 없음 | 운영 전환시 조회/수정 이력 로그 테이블 추가 검토 |
| 전자서명의 법적 효력 | 확인되지 않음 | 소속 기관(세무서)의 전자서명 인정 여부 사전 확인 필요 |
| 실제 개인정보 테스트 | 절대 사용 금지 | 테스트는 가상 데이터(홍길동/김영희 등)만 사용 |

## 7. QR 코드 생성 · 링크 전송 방법

1. `admin/qr.html` 접속 (관리자 목록화면 → 우측 상단 "QR 생성" 버튼)
2. "납세자 접속 페이지 주소"는 현재 페이지 기준으로 **자동 입력**됩니다.
   다른 도메인을 쓰신다면 직접 수정할 수 있습니다.
3. 필요시 참조번호(세무서 내부 관리용, 선택) 입력 후 "QR 생성" 클릭
4. 아래 5가지 방법으로 납세자에게 전달할 수 있습니다:
   - **QR 이미지 저장**: PNG 파일로 저장 → 인쇄물이나 카카오톡 이미지 전송에 사용
   - **링크 복사**: URL만 클립보드로 복사 → 메모/카톡에 붙여넣기
   - **공유하기**: 스마트폰의 기본 공유 시트가 열려 카카오톡·문자·메일 등을 바로 선택할 수 있습니다
     (PC 등 지원하지 않는 환경에서는 안내문이 자동으로 복사됩니다)
   - **문자 보내기**: 기본 문자 앱이 열리며 안내문+링크가 자동 입력됩니다
   - **이메일 보내기**: 기본 메일 앱이 열립니다
5. 하단의 **"기본 안내문"** 텍스트를 그대로 복사해서 카카오톡·문자·이메일 어디든
   붙여넣어 사용할 수 있습니다 (링크와 참조번호가 자동 포함됩니다).

💡 **실무 팁**: 스마트폰에서는 **공유하기** 버튼이 가장 빠릅니다 — 누르면 카카오톡이
공유 목록에 바로 뜨고, 선택만 하면 링크가 채팅창에 자동으로 들어갑니다. PC에서
작업 중이시라면 **QR 이미지 저장** 후 카카오톡 채팅창에 이미지+안내문을 함께
보내는 방법이 좋습니다.

⚠️ **카카오톡 "공식" 공유 버튼(카카오 링크 카드 형태)을 원하시면**: 카카오
디벨로퍼스(developers.kakao.com)에서 앱을 등록하고 JavaScript 키를 발급받아야
합니다. 지금은 앱 키가 없어도 되는 브라우저 표준 방식(공유하기)으로 구현했습니다.
나중에 앱 키를 발급받으시면 카카오 링크 카드(썸네일+제목 포함) 형태로 업그레이드
해드릴 수 있습니다.

## 8. 관리자 페이지 접속 방법

- 로그인: `admin/login.html` (이메일/비밀번호)
- 목록/검색: `admin/index.html` (로그인 안 되어 있으면 자동으로 로그인 화면으로 이동합니다)
- 상세보기: 목록에서 "상세" 버튼 클릭
- QR 생성: `admin/qr.html`
- ✅ 이제 로그인하지 않으면 관리자 화면의 데이터가 보이지 않습니다 (아래 9번 참고).

## 9. 관리자 로그인 설정 방법 — ⭐ 처음 한 번은 반드시 필요

관리자 계정은 Supabase 대시보드에서 직접 만듭니다 (회원가입 화면은 따로 없습니다 —
아무나 계정을 만들 수 없도록 일부러 막아둔 것입니다).

1. Supabase 대시보드 접속 → 왼쪽 메뉴 **Authentication → Users**
2. 오른쪽 위 **Add user** 클릭
3. 세무서 담당자 이메일과 비밀번호를 입력하고 생성
   (예: `admin@yourtax.go.kr` — 실제 사용하는 이메일 형식이 아니어도 되며, 로그인 아이디처럼 사용됩니다)
4. `admin/login.html` 접속 → 방금 만든 이메일/비밀번호로 로그인
5. 로그인에 성공하면 `admin/index.html`로 자동 이동합니다

담당자가 여러 명이면 2~3번을 반복해서 계정을 여러 개 만들면 됩니다.
비밀번호를 잊어버린 경우도 Supabase 대시보드의 Users 목록에서 재설정할 수 있습니다.

⚠️ **처음 설치하신 분만**: 기존에 `sql/schema.sql`을 이미 실행해서 데이터가 쌓여있다면,
`schema.sql`을 처음부터 다시 실행하지 마시고 `sql/migration-001-admin-auth.sql` 파일만
Supabase SQL Editor에서 실행해 주세요 (기존 접수 데이터가 유지됩니다). 새로 설치하시는
분은 `schema.sql` 한 번만 실행하면 로그인 정책까지 함께 적용됩니다.

## 10. 주민등록번호 암호화 설정 방법 — ⭐ 처음 한 번은 반드시 필요

주민등록번호는 데이터베이스에 평문(그대로)이 아니라 **암호화된 상태로 저장**됩니다.
암호화 키는 브라우저 파일(`js/config.js` 등)에는 절대 들어가지 않고, Supabase
데이터베이스 안의 별도 비공개 테이블(`app_secrets`)에만 존재합니다. 이 테이블은
API로는 관리자로 로그인해도 절대 조회할 수 없도록 잠가뒀고, 오직 DB 함수 내부
에서만 접근합니다. 제출할 때 암호화하고, 로그인한 관리자가 조회할 때만 그 함수
안에서 복호화되어 화면에 나타납니다.

> ⚠️ 예전 안내에는 `alter database ... set app.encryption_key = ...` 방식이
> 적혀 있었는데, Supabase가 보안 정책을 강화하면서 SQL Editor에서 이 명령을
> 실행할 권한 자체를 막아버렸습니다 (`42501: permission denied` 오류). 그래서
> 아래처럼 테이블에 저장하는 방식으로 바뀌었습니다 — `schema.sql`에 이미 반영돼
> 있으니 아래 순서만 따라 하시면 됩니다.

1. Supabase 대시보드 → **SQL Editor** → 새 쿼리
2. `sql/schema.sql` 전체를 먼저 실행합니다 (아직 안 하셨다면). 이 안에
   `app_secrets` 테이블이 자동으로 만들어집니다.
3. 새 쿼리를 하나 더 열고, 아래 명령의 `REPLACE_WITH_YOUR_OWN_SECRET_KEY`
   부분을 **직접 정한 비밀키**로 바꿔서 실행:
   ```sql
   insert into app_secrets (key_name, key_value)
   values ('encryption_key', 'REPLACE_WITH_YOUR_OWN_SECRET_KEY')
   on conflict (key_name) do update set key_value = excluded.key_value;
   ```
   - 영문+숫자를 섞어 20자 이상으로 만드는 것을 권장합니다.
4. 이 키는 **절대 잊어버리면 안 됩니다.** 키를 잃어버리면 이미 저장된 주민등록번호를
   다시는 복호화(원래 값 확인)할 수 없습니다. 회사 비밀번호 관리 도구나 별도의
   안전한 메모장에 꼭 백업해 두세요.

⚠️ **이미 예전 스키마(평문 저장)로 설치해서 데이터가 쌓여있는 경우**: `schema.sql`을
처음부터 다시 실행하지 마시고, `sql/migration-002-encrypt-rrn.sql` 파일을 열어서
2단계의 키 값을 바꾼 뒤 파일 전체를 실행하세요. 기존에 저장돼 있던 주민등록번호도
이 과정에서 함께 암호화로 전환되며, 데이터는 유지됩니다.

### 관리자 화면에서 주민등록번호가 보이는 방식
상세보기 화면에서는 주민등록번호가 기본적으로 `900101-1●●●●●●` 형태로 가려져
있고, 옆의 **"보기"** 링크를 눌러야 전체가 펼쳐집니다. 어깨너머로 보이는 걸
줄이기 위한 화면 표시 방식이며, A4 출력물과 엑셀 다운로드에는 실제 공문서/데이터
목적상 전체 번호가 그대로 표시됩니다.

## 12. 입력 편의기능 (하이픈 자동입력 / 주소검색)

- **주민등록번호·전화번호**: 숫자만 입력해도 자동으로 하이픈(-)이 붙습니다
  (예: `9001011234567` 입력 → `900101-1234567`로 자동 변환).
- **주소**: 직접 타이핑하지 않고 "주소검색" 버튼으로 다음(카카오) 우편번호 서비스
  팝업을 띄워 정확한 도로명주소를 선택합니다. 선택 후 "상세주소" 칸에 동/호수 등을
  추가로 입력합니다. 두 값은 제출시 하나의 문자열로 합쳐져 저장됩니다.
- 관련 로직은 `js/form-utils.js` 한 파일에 모아뒀습니다 (`attachRRNFormatter`,
  `attachPhoneFormatter`, `attachAddressSearch`).
- 주소검색은 외부 스크립트(`t1.daumcdn.net`)를 사용하므로, 사내망 등에서 해당 도메인이
  차단되어 있으면 동작하지 않을 수 있습니다. 이 경우 "주소검색을 눌러주세요" 입력창을
  직접 편집 가능하도록 `readonly` 속성을 제거해서 수동 입력으로 대체할 수 있습니다.

### 임시저장 (작성 중 데이터 보호)

작성 중인 내용은 입력할 때마다 자동으로 `sessionStorage`에 저장됩니다.
전화가 오거나 화면이 꺼졌다가 다시 들어와도, 심지어 실수로 뒤로가기를 눌렀다가
같은 링크로 다시 들어와도 **"이전에 작성하시던 내용이 있습니다. 이어서
작성하시겠습니까?"** 확인창이 뜨고, 예를 누르면 입력했던 내용이 그대로 채워진
1단계 화면으로 돌아갑니다 (저장된 단계로 바로 건너뛰지 않고 항상 1단계부터
시작합니다 — 서명 등 필수 확인을 건너뛰는 것을 막기 위함입니다).

- `sessionStorage`를 쓰는 이유: `localStorage`와 달리 **브라우저 탭/앱을 완전히
  닫으면 자동으로 사라집니다.** 주민등록번호처럼 민감한 값을 기기에 오래
  남겨두지 않으면서도, 실수로 인한 데이터 손실은 막기 위한 절충입니다.
- **전자서명은 임시저장 대상에서 제외**됩니다. 이어서 작성할 때는 서명 단계에서
  다시 서명해야 합니다.
- 제출이 정상적으로 완료되면 임시저장 내용은 자동으로 삭제됩니다.

### 이탈방지 (뒤로가기 · 닫기 확인창)

입력을 시작한 뒤 페이지를 벗어나려고 하면(뒤로가기, 탭 닫기, 새로고침 등)
브라우저 자체의 확인창이 뜹니다. 제출을 완료했을 때는 이 확인창이 뜨지
않습니다. 이 기능은 브라우저 표준 기능(`beforeunload`)을 사용하며, 일부
구형 브라우저나 특정 상황(예: 홈 화면으로 완전히 나가기)에서는 뜨지 않을
수도 있습니다 — 임시저장 기능이 그런 경우의 최종 안전장치 역할을 합니다.

### ⚠️ 제출 오류 임시 디버그 표시 (운영 전 제거 필요)

제출 오류 화면 하단에 `(개발 확인용) ...` 형태로 실제 오류 메시지가 작게 표시되도록
임시로 추가했습니다. Supabase 연결 문제를 콘솔 없이도 바로 확인하시라는 용도입니다.
**실제 납세자가 쓰기 시작하면 이 디버그 문구는 반드시 제거해 주세요** (기술적 오류를
그대로 노출하지 않기 위함). 각 폼 파일(`form.html`, `form-a.html`, `form-c.html`)의
제출 버튼 클릭 핸들러에서 `errBox.innerHTML` 부분을 찾아 `(개발 확인용) ...` 줄만
지우시면 됩니다.

## 14. PDF 직접 다운로드 기능

각 A4 출력 화면(`print/form-a-print.html`, `form-b-print.html`, `form-c-print.html`)에
버튼이 2개 있습니다.

| 버튼 | 동작 | 언제 사용 |
|---|---|---|
| 인쇄 / PDF 저장 | 브라우저 인쇄창을 엽니다 | 실제 프린터로 바로 인쇄할 때 |
| **PDF 다운로드** | 클릭 한 번으로 PDF 파일이 바로 저장됩니다 (인쇄창 없음) | 파일로 보관하거나 이메일 첨부할 때 |

**동작 원리**: 화면에 이미 정상적으로 그려진 내용을 이미지로 캡처해서 PDF에 담습니다
(`html2canvas` + `jsPDF`). PDF 안에 한글 폰트를 직접 심는 방식은 별도 폰트 파일
변환이 필요해 복잡하고 깨질 위험이 있어, 이 방식을 택했습니다. 다만 이 방식은
텍스트가 이미지로 담기기 때문에 **PDF 안의 글자를 마우스로 드래그해서 복사할 수는
없습니다** (인쇄물을 그대로 옮긴 것과 같다고 생각하시면 됩니다). 내용이 A4 한 장을
넘으면 자동으로 다음 페이지로 이어서 담깁니다.

파일명은 `서식이름_접수번호.pdf` 형태로 자동 지정됩니다
(예: `공동명의특례신청서_20260919001.pdf`).
